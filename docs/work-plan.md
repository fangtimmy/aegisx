# AegisX 工作计划

> 状态：初稿
> 日期：2026-07-15
> 依赖文档：[需求与技术方案](./requirements.md) | [技术选型](./technology-selection.md)

## 1. 交付策略

按纵向切片推进：先完成“手工题目 -> 本机 Agent -> 实时对话 -> 完成”，再增加容器、文件浏览和统计。每个阶段交付可运行功能，不先搭建没有真实调用方的进程、队列、插件或 package 边界。

技术基线：

- 单个 Hono API 进程管理 REST、SSE 和 AegisX Agent Runtime。
- SQLite 保存业务数据、Agent 消息、durable inbox 和 usage 来源。
- 本机使用独立工作目录，容器使用 bind mount 到 `/workspace` 的专属目录。
- REST 发送控制命令，SSE 直接转发当前 Pi 会话事件。
- 同时运行数量由进程内计数限制，满载时拒绝新运行。

## 2. 阶段与验收

### 阶段 0：最小技术验证

目标：确认 Pi 和容器工具转发两项关键假设。

任务：

- 建立最小 Bun + TypeScript 工程和统一 `check` / `test` 命令。
- 用 faux provider 创建 core `Agent`，注册 `finish_run` 并读取 SQLite 消息。
- 在独立本机目录执行一个工具命令并验证 abort 清理进程树。
- 用一次性 Docker 容器验证 `read`、`write`、`bash` 只操作 `/workspace`。
- 验证容器模式禁用了 Pi 默认宿主工具。
- 初始化 React、Tailwind v4 和 coss ui 页面。

验收：

- faux Agent 可以调用工具、完成运行并重新读取会话。
- 本机与容器工具只修改各自测试工作区。
- 容器工具无法读取宿主 AegisX 数据目录。

预计：1-2 个开发日。

### 阶段 1：赛事与题目

目标：完成赛事、题目和附件的持久化管理。

任务：

- 建立 SQLite schema 和迁移。
- 实现赛事和题目 CRUD。
- 实现附件流式上传、安全文件名、SHA-256 和原样复制。
- 实现赛事列表、赛事页和题目网格。
- 删除时将待清理目录移动到 `.trash`，提交数据库删除后清理；启动时清理残留。

验收：

- 可以从 UI 创建赛事和带附件的题目。
- 重启后数据与附件仍可读取。
- 附件复制前后 SHA-256 一致，路径型文件名被拒绝。
- 活动运行所属赛事不能被删除。

预计：2-3 个开发日。

### 阶段 2：本机 Agent 闭环

目标：完成第一条可用解题链路。

任务：

- 创建每次运行独立工作目录并保存实际提示词和配置。
- 在 API 进程内集成基于 Pi core `Agent` 的 Runtime。
- 实现 `running`、`paused`、`completed`、`failed`、`stopped` 状态转换。
- 实现 `finish_run`、人工消息、暂停、继续和停止。
- 通过 SSE 直接转发当前 Pi 事件，刷新后从 JSONL 读取历史。
- 实现运行树、运行概览和对话页。
- 限制同时运行数量，达到上限时返回明确错误。
- 启动时将残留 `running` 状态改为 `paused`。

验收：

- 两个本机运行使用不同工作区和会话文件。
- Agent 可以读取附件并通过 `finish_run` 完成。
- 用户可以发送人工消息、暂停、继续和停止。
- 页面刷新后历史会话可见，新事件继续实时显示。
- 终止前台命令后不残留子进程。

预计：4-5 个开发日。

### 阶段 3：容器与文件浏览

目标：提供容器隔离和工作区查看能力。

任务：

- 构建默认容器镜像并实现 create、exec、stop、rm。
- 将运行目录 bind mount 到 `/workspace`，网络固定为 `bridge`。
- 转发全部文件、搜索、编辑和 shell 工具，禁用 Pi 默认宿主工具。
- 应用 CPU、内存、PID、`no-new-privileges` 等容器限制。
- 实现文件树、文本预览、二进制元信息和下载。
- 运行结束后删除容器并保留工作区。

验收：

- Agent 的所有环境工具只作用于 `/workspace`。
- 容器无法访问 Docker socket、凭据和其他宿主目录。
- 暂停、停止和超时可以终止当前命令，必要时停止容器。
- 文件页拒绝路径穿越并能下载工作区文件。

预计：4-5 个开发日。

### 阶段 4：设置、统计与平台契约

目标：完成原始需求中的配置、统计和平台接口占位。

任务：

- 实现供应商、模型、API Key 和默认环境设置。
- 从 SQLite assistant message usage 计算运行、题目和赛事 Token 与费用。
- 实现题目 Token 对比图和运行明细表。
- 定义 `CtfPlatformAdapter` 类型。
- 未接入适配器时，将导入、靶机和 Flag 工具显示为不可用。

验收：

- 设置变更只影响新运行。
- Token 与费用汇总和 SQLite Agent 消息逐条计算一致。
- 未知模型价格显示“未知”。
- 没有适配器时，平台操作不会调用网络或导致 Agent 会话失败。

预计：2-3 个开发日。

### 阶段 5：安全与发布检查

目标：完成本地可用版本。

任务：

- 检查 loopback、Host/Origin、Content-Type 和日志脱敏。
- 检查附件、工作区路径和容器配置边界。
- 检查键盘操作、焦点、状态文本和窄屏布局。
- 补齐安装、配置和故障排查文档。

验收：

- 本机和容器两条端到端主流程通过。
- 路径穿越、默认工具旁路和恶意 Origin 测试被拒绝。
- API Key、Flag 和绝对路径不出现在通用错误与日志中。
- 桌面和窄屏关键页面无溢出或不可操作控件。

预计：2-3 个开发日。

## 3. 实施顺序

```text
Pi + Docker spike
  -> 赛事、题目、附件
  -> 本机 Agent 与实时对话
  -> 容器工具转发
  -> 文件浏览
  -> 设置与统计
  -> 平台接口占位
  -> 安全与 E2E
```

关键路径是 Pi core Agent -> AegisX Runtime -> 本机工具 -> SSE 对话 -> 容器工具。平台适配器、在线文件编辑和高级统计不阻塞 MVP。

## 4. 测试策略

不建立运行时、供应商、操作系统和浏览器的全组合矩阵。默认自动检查只保留：

1. 本机主流程：创建题目、启动 Agent、人工消息、暂停、继续和完成。
2. 容器隔离：附件可见，工具只能操作 `/workspace`，停止后无容器残留。
3. 重启恢复：历史 JSONL 可读，残留运行变为 `paused`。
4. 安全边界：文件名、canonical path、Origin、默认工具旁路和日志脱敏。
5. 统计：固定 JSONL 样本的 Token 与费用聚合。

真实模型调用只做手工 smoke test，不进入默认 CI。

## 5. 风险清单

| 风险 | 最小处理 |
| --- | --- |
| Pi 默认工具绕过容器 | 容器模式替换全部环境工具并做负向测试 |
| 本机模式可读取用户文件 | UI 持续提示其不是安全沙箱 |
| 暂停不能恢复当前命令 | 将暂停定义为 abort，继续时开始新一轮 |
| 进程退出中断运行 | 启动时将残留 `running` 标记为 `paused` |
| 容器命令未随停止结束 | 终止 exec 进程树，必要时停止容器 |
| 附件或路径破坏宿主文件 | 流式落盘、安全 basename 和 canonical path |
| 恶意网页调用本机 API | loopback、Host/Origin 校验和严格 Content-Type |
| 模型 usage 或价格缺失 | 保存原始 assistant message，未知费用显示未知 |

## 6. 完成定义

- 行为符合当前阶段验收标准。
- 有一条覆盖该功能主要失败方式的自动检查。
- 类型检查、lint 和相关测试通过。
- 错误不泄漏凭据、Flag 或宿主路径。
- 前端在桌面和窄屏下可操作。

## 7. 粗略工期

单人顺序开发约 15-21 个开发日，不包含真实 CTF 平台适配器、在线文件编辑器和高级统计。阶段 0 失败时先重新选择单一后端运行时，再重新估算。
